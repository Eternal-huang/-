# 电氢协同 · 大创项目工作台

**把每周任务、仿真步骤和团队进展放到同一个入口。**

本仓库用于天津大学大学生创新训练项目的学习与协作，研究方向为**含电化学储能的电解制氢系统在配电网中的主动支撑与协同调控**。

当前采用“全体成员独立完成相同任务”的方式推进：每个人都亲自搭建模型、运行仿真、解释结果，再提交可复现的成果。工作台帮助大家明确本周要做什么、怎样验收、遇到问题去哪里讨论。

[查看任务与指南](https://da-chuang-workflow.foggy-wood-5229.chatgpt.site) · [提交与讨论](https://github.com/Eternal-huang/-/issues) · [部署运行记录](https://github.com/Eternal-huang/-/actions/workflows/pages.yml)

> 上面的任务与指南链接是负责人可访问的预览入口。供群成员使用的正式网站地址，请到 [Settings → Pages](https://github.com/Eternal-huang/-/settings/pages) 查看部署成功后显示的 **Your site is live at…**。本 README 不将尚未核实的地址标为已上线。

## 第一次使用

1. 打开正式网站，在“每周任务”中填写昵称、选择周次。
2. 先阅读任务内容与验收标准，再根据“仿真指南”完成实验。
3. 完成任务后勾选清单，填写结果、阻塞点和成果链接。
4. 点击“生成 GitHub 提交”，在打开的 GitHub 页面补充文件。
5. 点击 **Submit new issue** 正式提交，之后在对应 Issue 中交流和反馈。

**网页上的勾选是当前浏览器的草稿；正式提交到 GitHub 后，团队才能看到这条记录。** 浏览网站无需填写令牌，正式提交需要登录自己的 GitHub 账号。

| 论文写作 | 按问题、模型、方法、证据及待补实验整理写作提纲 | [新建写作记录](https://github.com/Eternal-huang/-/issues/new/choose) |

建议从 [论文阅读指南](docs/reading-guide.md) 开始：先读电氢储能综述，再读电解槽调频建模论文，最后对照近期预印本。每篇卡片都附来源链接与三个阅读问题。

网页编辑器按记录类型和论文分别保存本机草稿，支持导出 / 复制 Markdown、生成 GitHub Issue。正式提交后，团队通过 Issues 查阅与讨论；这些记录不会混入每周仿真完成率。过长的笔记会先下载 Markdown，需把内容粘贴到 GitHub 页面再提交。

起步文献不是完整的文献综述；预印本已单独标注。候选研究问题尚未确认为创新点，实验计划不能当作已完成结果。

## 当前任务安排

### 第一周：跑通三相配电网基础模型

- 建立“三相电源 → 线路 → PCC → 三相负荷”模型。
- 正确测量并导出 `U_pcc`、`P_grid`、`I_abc`。
- 绘制电压、功率和三相电流，保存绘图脚本与仿真数据。
- 解释稳态结果，检查仿真时长是否覆盖设置的事件。

验收重点：**模型可运行、信号维度正确、图表单位清楚、结果可以复现。**

### 第二周：负荷扰动与储能—制氢简化模型

- 在第一周模型中完善第二处三相负荷投切，观察投入前后的变化。
- 建立带功率限制、SOC 边界及响应时间常数的储能简化模型。
- 建立带功率上下限及爬坡约束的电解槽简化模型。
- 运行统一负荷扰动，检查功率平衡并整理交付成果。

第二周统一参数如下：

| 项目 | 参数 |
| --- | --- |
| 储能容量 | 10 kWh |
| 储能功率范围 | −20～20 kW |
| SOC 初值 / 下限 / 上限 | 0.50 / 0.20 / 0.80 |
| 储能时间常数 | 0.1 s |
| 电解槽初始功率 | 20 kW |
| 电解槽功率范围 | 5～30 kW |
| 电解槽升、降功率速率 | 均为 2 kW/s |
| 统一负荷扰动 | 10 s 时由 50 kW 增至 60 kW |
| 仿真时长 | 30 s |

功率采用统一约定：

```text
P_grid = P_load + P_el − P_bat
```

其中，`P_bat > 0` 表示储能放电，`P_bat < 0` 表示储能充电。功率统一使用 kW；计算 SOC 时注意秒与小时的换算。

> 第一周三相测量模型与第二周简化功率模型分别验收。理想固定频率电源不能用于验证频率跌落或虚拟惯量效果；当前阶段先验证负荷投切、测量与功率平衡。

## 私有论文库：仅编辑者可见

当前工作台仓库是公开仓库，不能限制其中某个目录只供编辑者查看。**不要把受限 PDF 上传到本仓库或公开 Issues。** 公开 PDF 上传入口已关闭，私有库尚未接入，上传和阅读按钮暂不可用。

接入方式：

1. 负责人另建一个个人账号下的 **Private** 仓库，例如 `dachuang-papers`，勾选 Add a README。
2. 在新仓库 Settings → Collaborators 中，仅邀请当前项目的编辑者。两边的成员权限不会自动同步；以后增删编辑者时也要同步维护。
3. 提供新仓库地址，验证私有属性及成员范围后接入工作台。
4. PDF 的上传和阅读跳转至私有仓库，由 GitHub 登录权限控制；公开工作台不下载、缓存或发布 PDF。

个人私有仓库的协作者具有读写权限，因此只邀请编辑者即可建立对应访问范围。已下载的本地副本无法通过撤销权限远程收回。

公开站点部署增加 PDF 检查，有 PDF 时停止发布；该检查不把公开仓库本身变为私有。原公共论文目录生成脚本已禁用。

## 团队进度如何更新

正式 GitHub Pages 版本通过以下流程更新：

**成员提交或编辑进展 Issue → GitHub Actions 读取报告 → 生成团队快照 → 重新部署网站。**

- 同一 GitHub 账号、同一周次保留最近更新的一条有效报告。
- 不同账号即使填写相同昵称，也不会合并。
- 进度是成员自报；是否通过验收，由队长在对应 Issue 中反馈。
- 更新需要等待部署完成，不是实时同步；可到 Actions 查看运行结果。
- 负责人预览版本不会随着 GitHub Issues 自动刷新团队快照，以正式网站与 Issues 为准。

提交表单会生成一段用于统计的 JSON，请保留它。**如果直接在 GitHub 编辑完成情况，需要同步修改 JSON 中的 `completed`；只修改文字清单不会更新统计。**

## 遇到问题怎么办

| 情况 | 处理办法 |
| --- | --- |
| 勾选了任务，其他成员却看不到 | 勾选只保存在本机；请生成并正式提交 GitHub Issue |
| 已提交，网站还没有更新 | 查看 Actions 是否完成，然后点击“刷新记录” |
| 仿真报错 | 在 Issue 中附上报错原文、相关模块截图、参数和复现步骤 |
| 模型跑通，但结果无法解释 | 写出预期与实际结果的差别，说明测量位置和功率方向 |
| 浏览器更换或草稿丢失 | 使用“导出本机草稿 JSON”备份，在新浏览器导入 |

讨论时尽量附上能复现问题的信息，避免只写“运行不了”或“结果不对”。

## 负责人部署说明

1. 打开 [Settings → Pages](https://github.com/Eternal-huang/-/settings/pages)，将 **Source** 设为 **GitHub Actions**。
2. 打开 [Publish project workspace](https://github.com/Eternal-huang/-/actions/workflows/pages.yml)，点击 **Run workflow**，分支选择 `main`。
3. 等待部署成功，从 Pages 设置或部署输出中取得实际网站地址。
4. 将正式地址发给组员，并确认仓库的 Issues 功能已启用。

若 Pages 仅显示 Upgrade，说明当前账号或仓库设置限制了该功能。免费套餐可使用公开仓库部署；将仓库公开也会公开源码、Issues 和运行记录，需由负责人决定。

后续推送到 `main`，或进展 Issue 发生变化，均会触发部署。
